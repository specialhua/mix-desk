# 桌面端写作体验规划

目标：在 Web 后台的写作页之外，用 MyGo 和它生态里的组件补上浏览器给不了的写作体验。

## 原则

- **编辑器不重写**：正文编辑、CRDT 草稿和协作仍用 Web 后台的 haklex 编辑器。桌面端只做外围的原生能力。
- **维护边界不变**：只改 `apps/desktop`，只用 mx-core 已公开的接口和 Web 后台已有的 DOM（像现在的 `aria-label` 依赖一样，在 `bridge.go` 集中声明）。原生端调 API 时，用钥匙串里的会话令牌（`Authorization: Bearer`）。
- **能用生态就不自造**：Onevra（外壳、组件、聊天、Markdown、命令面板）、mygo 自带的 `GlobalShortcut`、`NewFlyout`、`Network`、通知，以及 SQLite、Watch 等官方插件。

### 1. 专注模式

- **入口**：快捷键 `⇧⌘F`（“显示 → 专注模式”菜单项），右下角设置球里的开关，命令面板。
- **进入**：在当前窗口内铺满，不进入系统全屏：收起原生侧边栏，给页面加上 `mx-desktop-focus` 类，隐藏写作页的顶栏。正文宽度不变，免得编辑器工具栏放不下、出现横向滚动。
- **退出**：再按一次，侧边栏恢复到进入前的样子；离开写作页也会自动退出。
- **打字机滚动**（可选，设置里保存）：光标所在行保持在编辑区 40% 的高度（略高于正中，给斜杠菜单在光标下方留出空间，否则菜单会向上翻转、被工具栏盖住），正文底部留出半屏空白，最后几行也能滚到中间。专注模式内外都能开。半屏空白只加在最外层编辑器上：提示块（Warning 等）里嵌套着自己的 Lexical 编辑器，也带 `data-lexical-editor`，加上去会把提示块撑高。
- 只在写作页（`/posts/edit`、`/notes/edit`、`/pages/edit`）生效。

### 2. 悬浮状态栏与液态玻璃

写作页上，网页铺满整个内容区，标题栏和状态栏都用 MyGo 原生 UI 画成液态玻璃胶囊，悬浮在网页上（glass 插件的 `Glass{Native: true}`：macOS 26 及以上是系统的 NSGlassEffectView，能透出下面的网页；其他系统用插件的着色器）：

- **标题栏**：面包屑一个胶囊；侧边栏收起时，侧边栏开关下也垫一块圆形玻璃。其他页面的标题栏也用同样的胶囊，网页仍从标题栏下方开始。
- **写作页顶部**：注入样式给写作页留出标题栏的高度（`--mx-desktop-header`）。
- **右下角设置球**：平时只有一颗带设置图标的玻璃球。点一下，统计（字数、时长）、专注、打字机三个玻璃胶囊从球的位置依次向左飞出（位移加缩放，原生玻璃跟着元素的变换走，但不跟透明度，所以不用淡入）；专注和打字机是开关，开启时是强调色的玻璃。再点球，胶囊飞回球里收起，图标同时转回。
- 后台是整页固定高度、内部滚动的布局，写作页的文档本身不应滚动。编辑器把光标滚进视野时可能连带滚动整个文档，底部会露出一条空白，所以注入脚本会把文档的滚动位置保持在 0。

内容：

- **字数**：中日韩文字每个算一个字，英文和数字按词算，读的是编辑器正文。
- **写作时长**：显示“本次 4m · 累计 1h 20m”。本次从打开这篇文章算起，下次打开从 0 开始；累计存在本机用户数据目录的 `writing-time.json`（按文章记秒数）。只在窗口显示时计时，睡眠后恢复的那一下最多计两个间隔（40 秒）。
  - 按什么记：路由里有文章 id（`?id=`）就按文章记，一篇文章换哪个草稿分支都算同一篇；还没发布的新文章按草稿 id（`?draftId=`）记，发布拿到文章 id 时把草稿的累计并过去；没保存过的新文章先记在内存里，第一次保存出草稿 id 时并过去。
- 草稿保存状态网页顶部已有，状态栏不重复显示。
- 右侧放打字机滚动和专注模式的开关。

### 3. 全局速记“想法一瞬”

- **唤出**：全局快捷键 `⌥⌘N`。菜单和设置里提示这个快捷键。
- **浮窗**（原生 Flyout，不加载 web view，瞬间弹出）：
  1. 选择已有的想法标题，或新建一个；
  2. 随意粘贴或输入内容；
  3. 选一个分类：闪念、网页、书籍、新闻、论坛，也可以自定义新分类（保存在设置里）。
- **本地存储**：每个想法标题一个文件，放在用户数据目录的 `ideas/` 下。文件里按“序号，时间，内容（含分类）”逐条追加。
- **防止追加错**：浮窗里始终明确显示当前要追加的标题；按标题的稳定 ID（不是标题文字）定位文件；切换标题时会清空输入框，并显示该标题已有的条目数和最后一条，确认无误再追加。
- **生成草稿**：用户确认后，选择手记或博文，用整理好的内容生成一篇草稿，然后在主窗口打开它的写作页，自动展开写作页的 AI 面板，预填提示词，**但不发送**。预填内容大致是：“以下是我按序号记录的想法，请注意不同序号之间内容的关联性，为我生成文章标题和可参考的论点。”用户可以改完再发送，或者直接在编辑器里整理草稿。
- 待确认：AI 面板的输入框能否从外部预填（只读后台代码确认，必要时用注入脚本填值，不改后台）。

### 4. 系统服务：发送到 Mix Space 草稿

- 在其他应用里选中文字或链接，右键 → 服务 → “发送到 Mix Space 草稿”。
- 默认追加到“想法一瞬”的某个标题下（弹出浮窗让用户选），也可以直接生成新草稿。
- 待确认：MyGo 是否支持注册 macOS Services（`NSServices` 和服务提供者）。不支持的话，用 URL Scheme（`mixspace://`）加一个快捷指令作为替代。系统“分享”菜单需要单独的扩展，不在本期范围。

### 5. AI 写作助手悬浮球

- 写作页右下角一个原生悬浮球，可以收起到边缘。
- 点开后是 Onevra 聊天面板，回复用流式 Markdown 显示，调用服务端的 `ai-writer`、`ai-summary`、`ai-translation` 等接口：
  - 生成标题、slug 和摘要，一键填回；
  - 选中正文后润色或改写，以对比形式确认后再替换；
  - 查看翻译状态。
- 和写作页自带的 AI 面板分工：悬浮球负责快速、一次性的操作，长对话仍用页面里的面板。

## 依赖的后台 DOM（写作相关）

在 `bridge.go` 里集中维护，后台改版时在那里适配：

- 编辑器正文：最外层的 `[data-lexical-editor="true"]`（排除嵌套在提示块等里面的），Markdown 格式是 `.cm-content`
- 写作页：`form:has([data-lexical-editor], .cm-content) > section`（顶部留出标题栏高度），它的第一个子元素是顶栏（专注模式隐藏）
